Frequently asked questions

Status, password handling and setup for the Renpho MCP server.

Is this an official Renpho project?

No. It is independent and not affiliated with Renpho. It uses the unofficial renpho-api client, which was reverse-engineered, so Renpho can change or block its API at any time. Pin a release tag if you need stability.

What happens to my Renpho password?

You put it in a local .env file that is passed to the container at run time. The SDK sends it to Renpho to log in. It is never copied into the image, and the server has no network listener. Your AI model provider sees only the query results the assistant receives, not your password.

Can it change or delete my data?

No. All three tools are read-only, and the server does not expose the SDK's upload function.

Has it been tested on a real Renpho account?

Not yet publicly. The formatting and filtering logic has unit tests on invented data and the container builds and lists its tools in CI. A live read-only check against a real account is planned, and this page will say so when it is done.

Which Renpho app does it work with?

It uses the Renpho Health API through the renpho-api client. Accounts on the legacy Renpho app may not work.

Do I need Docker?

The container is the recommended route. If you have Python 3.10+ and uv you can also run uv run renpho-mcp from a clone with RENPHO_EMAIL and RENPHO_PASSWORD set.

Which AI clients work?

Any client that can start an MCP server over stdio, including Claude Code, Claude Desktop and Cursor.

How many tokens does it use?

Output is compact tab-separated text and you choose the columns, dates and period. A measured comparison against other servers has not been published, so there is no figure yet.

How do I report a problem or suggest something?

Open an issue in the GitHub Issues tab. Please do not post vulnerabilities publicly.
